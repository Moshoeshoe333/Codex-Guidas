# Spirit — User Interface 33 (U-01…U-33)

**Framework:** CG-TT33 v0.3.0-draft  
**Analysis question:** Does what a person sees, hears or can do match the decision, authority and persisted state—no more and no less?

## Circle A — Existence and reach (U-01…U-11)

| ID | Tier | Assessment question / intent |
|---|---|---|
| U-01 | Screen and interaction inventory | Are screens, modals, routes, notifications and material interaction surfaces inventoried? |
| U-02 | Navigation integrity | Do navigation paths, deep links and back/restart behaviour lead to valid, authorized states? |
| U-03 | Component map | Are shared components and near-duplicates understood, with intentional variants documented? |
| U-04 | Decision-display binding | Does UI presentation bind to canonical decision/status identifiers rather than reimplementing policy? |
| U-05 | State matrix | Are loading, empty, error, pending, success, stale, offline and restricted states defined where applicable? |
| U-06 | Input and validation paths | Are user inputs validated, normalized and explained consistently with backend/domain contracts? |
| U-07 | Accessibility | Are decision-critical controls and information accessible to intended users and assistive technologies? |
| U-08 | Localization and language | Are user-facing terms and translations governed, contextually reviewed and consistent with canonical concepts? |
| U-09 | Offline and connection indicators | Are offline, queued, syncing, stale and failed states truthful and distinguishable? |
| U-10 | Restart and recovery UX | Does the interface accurately represent restored, pending, expired or unrecoverable state after restart? |
| U-11 | Platform envelope | Are supported devices, OS versions, browser constraints and known limitations declared and tested proportionately? |

## Circle B — Truthfulness and trust (U-12…U-22)

| ID | Tier | Assessment question / intent |
|---|---|---|
| U-12 | Claim-tone discipline | Does every user-facing claim stay within the evidence and authority actually available? |
| U-13 | Severity and decision honesty | Are severity, confidence, recommendation and final decision distinguished? |
| U-14 | Capability disclosure | Can users understand what the system can and cannot detect, verify or guarantee? |
| U-15 | Error display integrity | Are errors useful and actionable without leaking sensitive internals or misleading users? |
| U-16 | Observed vs derived disclosure | Can users distinguish submitted facts, verified assertions, estimates and system-derived conclusions where material? |
| U-17 | Empty/loading state safety | Do empty, delayed or loading states avoid implying success, safety or absence of risk? |
| U-18 | Explanation and challenge path | Can users understand why a material warning/decision occurred and how to challenge or correct it where appropriate? |
| U-19 | Fixture-driven presentation | Are important UI states demonstrable from representative, controlled fixtures? |
| U-20 | Timing and freshness honesty | Are delays, stale data, last-updated times and asynchronous outcomes represented accurately? |
| U-21 | Visual/content resilience | Does the interface remain usable under long text, localization, large text, zoom and constrained screens? |
| U-22 | Consent and user control | Are consent, permission, withdrawal, access and deletion actions clear and scoped where relevant? |

## Circle C — Verification and change discipline (U-23…U-33)

| ID | Tier | Assessment question / intent |
|---|---|---|
| U-23 | State-matrix tests | Are UI states covered by appropriate component, snapshot, property or interaction tests? |
| U-24 | Copy and content governance | Are decision-critical words, translations and disclosures reviewed and versioned as part of the product contract? |
| U-25 | Golden-fixture parity | Do UI fixtures represent the same canonical decision cases and versions used by the domain/persistence layers? |
| U-26 | Accessibility verification | Are automated and manual accessibility checks performed, with known limitations recorded? |
| U-27 | Offline end-to-end experience | If offline use is promised, has the complete user workflow been exercised under realistic loss/reconnect conditions? |
| U-28 | Deep-link and alternate-entry regression | Do alternate entry paths preserve the same authorization and decision semantics? |
| U-29 | Interaction performance | Is latency measured on representative devices and workflows? |
| U-30 | Update and migration UX | Does the interface handle old, incompatible, pending or migrated data without hiding uncertainty or losing user work? |
| U-31 | Telemetry and network transparency | Are analytics, diagnostics and network transmissions inventoried, minimized, disclosed and consented/authorized as required? Verify claims through configuration and network observation; do not assume telemetry-free is always the right goal. |
| U-32 | Visual regression and determinism | Are important visual states reproducible and regression-checked where worthwhile? |
| U-33 | User-readable record access | Can users inspect or export an understandable representation of relevant records and decisions, subject to privacy, security and role boundaries? Raw database access is not a universal requirement. |

## Profile notes

- Consent, erasure, accessibility, language, notification and telemetry obligations depend on product, jurisdiction and user group, but must be assessed rather than assumed.
- User-facing access to a record must not expose another person's data or bypass authorization.
- “No telemetry” is a possible product promise, not a default framework mandate. The universal requirement is truthful, minimized and governed data transmission.

**Passport rule:** test what a real user can see and do, not merely what the component source appears to intend.
