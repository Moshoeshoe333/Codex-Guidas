# Retrospectives

A retrospective converts a meaningful event, release, incident, experiment or abandoned direction into actionable learning.

## Rules

- Record what happened, not what we wish had happened.
- Separate facts, reports, interpretations and hypotheses.
- Discuss process and system conditions without personal blame.
- Include successes as well as failures.
- Preserve negative and contradictory evidence.
- Identify one or more concrete changes, owners and verification methods.
- Link to exact project commits, runs, issues and defect records.
- Do not claim a lesson is verified until its control has been tested.

## Template

Use [retrospective-template.md](retrospective-template.md). Keep the retrospective in this repository only when the learning is cross-project or strategically reusable; project-specific operational incident records should remain in the owning project, with a link here.
