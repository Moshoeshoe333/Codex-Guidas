# Scorecards

Scorecards make progress and risk visible without turning activity into vanity metrics.

## Principles

- Measure outcomes, not document or commit volume.
- Every metric needs a definition, source, owner, cadence and known limitations.
- Separate leading indicators from lagging outcomes.
- Show unknown or unavailable data as unknown, not zero.
- Never reward unsafe speed or discourage reporting defects.
- A scorecard informs a decision; it does not make the decision automatically.

## Weekly portfolio review

The [weekly portfolio scorecard](weekly-portfolio-scorecard.md) is an **optional planning prompt**, not a required weekly reporting obligation. The repository currently contains the template but no dated completed examples establishing routine use. Do not claim adoption or trend data from the existence of the template.

Use it only when it changes a real prioritisation decision. Keep one primary outcome, explicit blockers and a short list of work deliberately not pursued. The provisional 80/10/5/5 allocation is a planning hypothesis, not a performance target; adjust it when capacity, livelihood obligations or evidence changes. Do not invent work to fill a percentage when a project is blocked.

Do not create an archive of empty or synthetic scorecards. If repeated real use demonstrates value, add dated completed records under `scorecards/archive/` with source evidence and known limitations. If it remains unused, retire or simplify the template rather than maintaining reporting theatre.
