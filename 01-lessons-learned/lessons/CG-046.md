# CG-046 — A zero-count source-pattern scan is not a complete output-safety review

- **Status:** Derived
- **Date discovered:** 2026-11-25
- **Last reviewed:** 2026-11-25
- **Source project:** ScoutSA
- **Source artifact/path:** `prototype/README.md`, UI-008 sections; `prototype/verification/UI-008-SINK-EVIDENCE-LEDGER-2026-11-20.md`
- **Commit / CI run / issue:** Exact head `125c48082633ec4bb744f5734b78cc659441e8ba`; hosted workflow #1087, run `45606385341`
- **Severity and rationale:** High — a narrow source-pattern count can be misread as a complete security conclusion.
- **Applicability:** General; especially web rendering, URL handling, exports and file handoffs

## Event
The ScoutSA prototype records a bounded 21-page source-text inventory with zero `.innerHTML =` assignments after targeted renderer changes. The same README explicitly keeps UI-008 open because dynamic output contexts, URLs, exports and handoffs still require review.

## Expected behaviour
Security conclusions should be limited to the exact pattern, files, paths and tests examined. A clean count for one sink pattern must not be generalized to all output contexts or attack surfaces.

## Actual behaviour
The project distinguishes the zero-assignment source count and selected hostile-renderer regressions from a complete output-context review. It keeps UI-008 open and identifies remaining expression-level/runtime, URL, export and handoff review.

## Impact
A narrow mitigation can be mistaken for a complete security sign-off, allowing unreviewed dynamic contexts to inherit confidence they have not earned.

## Root cause
Measurement-scope error: a bounded static inventory answers only the question it was designed to count.

## Corrective action
Maintain a sink evidence ledger with file, line, source, context, risk, mitigation, exact test and residual review state. Review URLs, exports, handoffs and dynamic output contexts independently.

## Preventive / detective control
For every security metric, publish its denominator, scope, exclusions and unresolved paths. Keep the relevant gate open until each required sink/context has its own evidence.
