# Purpose and scope

## Primary outcome

Codex-Guidas is a cross-project engineering knowledge base. Its operational priority is to help teams find relevant prior failures, constraints and verified controls before repeating a costly mistake. It should improve decisions and reduce recurring defects—not maximise document count or framework count.

The core learning path is:

    detect or decide → search prior knowledge → inspect evidence
    → adapt a control → verify in the owning project → record the result

A lesson is useful only when its provenance, maturity, applicability and limits are discoverable.

## What belongs here

- Reusable engineering lessons and defect patterns drawn from project evidence.
- Evidence and decision practices that preserve accurate claims.
- Architecture, security, privacy, safeguarding, testing and operational principles that support the primary outcome.
- Bounded knowledge packs that retain provenance and require validation in the adopting project.
- Experimental or proposed methods, clearly separated from adopted operating practice.

## What this repository does not do

- It does not replace a project's source of truth, issue tracker, release gate or incident authority.
- It does not certify security, privacy, legal compliance, product quality or commercial demand.
- It does not make an unverified source observation into a reproduced defect.
- It does not authorize an agent or automation to change production code.
- It does not treat a framework, checklist, score or document count as proof of effectiveness.

## Scope discipline

The broader methodology and doctrine material is supporting context. A method should be used only when it answers a real question; it should not become mandatory ceremony merely because it exists. Proposed or incomplete frameworks remain explicitly labelled and must not displace the evidence-first operating path.

The repository is presently maintainer-led. Multi-contributor governance, independent review capacity and any external reuse licence remain open decisions. No external licence is granted by this purpose statement.

## Success measures

Start with manual measures: whether maintainers searched before fixing, whether a prior record was found, whether a prior control was applied, whether recurrence occurred, and whether closure includes exact regression evidence. Do not build dashboards or bots until repeated use demonstrates a bottleneck.
